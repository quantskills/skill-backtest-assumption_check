# 九大审计维度：检查点 / 证据 / 判定 / 修复

> 这是本 skill 的心脏文档。九个维度逐条给出：**判定什么**、**证据从哪来**（代码取证 / 数据验证）、**判定标准**（PASS / WARN / FAIL / INFO）、**修复指引**。
> 判定基线对齐生态 `skill-backtest` 标准协议：T+1 开盘成交、Top 等权、双边 15bp、A 股涨跌停规则。

通用判定口径：

- **PASS**：符合基线，无问题。
- **WARN**：有隐患或披露不清，但当前证据下不必然失效。
- **FAIL**：违反基线，会系统性扭曲结论。
- **INFO**：无法验证（缺材料）或仅为规范化建议。

---

## 轴 1：成交时点与未来函数（Execution timing & lookahead）

**判定什么**：信号是在哪个时点生成的，假设在哪个时点成交；是否用了成交时点之后才可得的信息；是否遵守 T+1 开盘成交。

**证据来源**
- 代码取证：搜 `shift`、`iloc`、`loc`、日期错位、`close` 同时用于信号与成交价；信号列是否 `shift(1)`。
- 数据验证：`detectors/execution_timing.py` —— 用 panel 做前缀回放，比较「用当日 close 生成信号、按当日 close 成交」与「T+1 开盘成交」两条净值曲线。

**判定标准**
- FAIL：信号生成与成交用了同一时点信息（如 close→close），且未做任何前视隔离。
- WARN：用了 T+0 成交假设但无说明；或部分路径泄露。
- PASS：明确的 T+1 开盘成交，信号与成交时点严格隔离。

**修复指引**：信号统一 `shift(1)`；成交价用 `open[T+1]`；回放验证两条曲线差异。深挖联动 `skill-numerical-leak-check`（前缀重放 + 未来扰动）。

---

## 轴 2：交易成本（Trading costs）

**判定什么**：回测是否计入佣金、印花税、滑点、冲击成本；A 股双边成本假设是否合理。

**证据来源**
- 代码取证：搜 `cost`、`commission`、`fee`、`slippage`、`tax`、`stamp`；成本是否从收益中扣减。
- 数据验证：`detectors/cost_model.py` —— 从净值 / 收益序列反推隐含成本，与假设成本对比。

**判定标准**
- FAIL：成本 = 0 或完全未提成本（长期高换手下结论必然虚高）。
- WARN：只算了佣金、漏了印花税 / 滑点 / 冲击；或成本参数明显过低。
- PASS：双边成本显式建模（A 股参考：佣金 ≈ 2.5~3bp + 印花税卖出 5bp + 滑点），且从毛收益中扣减。

**修复指引**：按生态基线双边 15bp 起算，或按实际账户参数建模；成本从毛收益中扣减；对成本做敏感性分析。

## 轴 3：涨跌停与停牌（Price limits & suspensions）

**判定什么**：买入日是否一字涨停（买不进）、卖出日是否一字跌停（卖不出）、停牌股是否处理。

**证据来源**
- 代码取证：搜 `limit`、`paused`、`suspend`、`停牌`、涨跌停剔除逻辑。
- 数据验证：`detectors/price_limits.py`（比对成交价与涨跌停价位可达性）+ `detectors/suspensions.py`（停牌日持仓检查）。

**判定标准**
- FAIL：策略「成交」在涨停一字板 / 停牌日，未剔除也未标记。
- WARN：只剔除了涨停，没处理跌停卖出 / 停牌。
- PASS：买入剔除涨停（一字）、卖出剔除跌停（一字），停牌日无成交且持仓不参与收益。

**修复指引**：按涨跌停规则标记不可成交；停牌日持仓保留、不计收益或按规则处理；对照真实行情验证「成交价是否可达」。

## 轴 4：幸存者偏差（Survivorship bias）

**判定什么**：股票池是否用当前成分回填历史；退市 / 新股是否处理。

**证据来源**
- 代码取证：股票池来源是否固定为「当前指数成分」或「今日全市场列表」；有无历史成分重建。
- 数据验证：`detectors/survivorship.py` —— 给定历史成分 / 生命周期数据，重建每日池，统计缺了多少历史名（退市股缺失比例）。

**判定标准**
- FAIL：用当前成分回填全部历史；无退市 / 新股处理。
- WARN：成分随时代更新，但退市收益缺口未统计。
- PASS：按披露日重建历史股票池，含退市 / 停牌期，收益归零或按真实路径处理。

**修复指引**：按快照重建历史池；退市股收益归零直至退市日；统计幸存者偏差导致的收益缺口。

## 轴 5：参数自由度与多重比较（Parameter freedom & multiple testing）

**判定什么**：试了多少参数 / 因子组合；样本量多大；Sharpe 是否只是多次试验的幸存者。

**证据来源**
- 代码取证：参数网格、for 循环扫参、`trial` / `n_params` 统计；报告是否披露试验次数。
- 数据验证：`detectors/parameter_freedom.py` —— 输入试验次数 N、样本量、年化波动，计算 Deflated Sharpe / 期望最大 Sharpe。

**判定标准**
- FAIL：大量扫参但未做任何多重检验校正，且无样本外验证。
- WARN：有样本外 / 交叉验证，但未披露试验次数。
- PASS：披露试验次数，报告校正后 Sharpe（Deflated Sharpe），有独立样本外确认。

**修复指引**：记录全部试验 → 计算 Deflated Sharpe → 预留 holdout / 样本外。深挖联动 `skill-backtest-overfit`（多重检验下的选择偏差）。

## 轴 6：数据对齐与复权（Data alignment & adjustment）

**判定什么**：复权一致性、除权除息处理、停牌日、财报 point-in-time（财报时点前视）。

**证据来源**
- 代码取证：数据 join 键是否含日期错位；是否用未复权价混算收益；财报数据是否用「发布日」而非「报告期」。
- 数据验证：`detectors/data_alignment.py` —— 校验复权价跨除权日的一致性、除权缺口。

**判定标准**
- FAIL：混用复权 / 未复权价；财报用报告期而非发布日（point-in-time 前视）；join 产生未来数据。
- WARN：复权口径未声明；分红除权仅部分处理。
- PASS：统一复权口径，除权除息一致，财报用 point-in-time，日期对齐无未来信息。

**修复指引**：统一前复权口径；按除权除息事件校验价格连续性；财报字段用 announce_date。

## 轴 7：换手与容量（Turnover & capacity）

**判定什么**：实际换手多少；篮子成交额占成交量的比例；冲击成本是否被忽略。

**证据来源**
- 代码取证：是否有权重序列；是否计算换手；篮子规模假设。
- 数据验证：`detectors/turnover_capacity.py` —— 从权重序列算单边换手；篮子成交额 / 成分股 ADV。

**判定标准**
- FAIL：高换手但零成本假设，且篮子规模远超 ADV（影响买不进去 / 冲击大）。
- WARN：有换手统计，但容量 / 冲击未评估。
- PASS：换手显式计入成本；篮子占日成交额比例合理（如 <5%），容量受限个股已说明。

**修复指引**：按权重序列算实际换手并入成本；用 ADV 评估容量；容量敏感标的单独披露。

---

## 轴 8：基准与超额（Benchmark & excess returns）

**判定什么**：基准是否可比；是否悄悄换基准；超额是否剔除市场 / 风格。

**证据来源**
- 代码取证：基准定义、超额计算口径、基准是否随市场变化。
- 静态判定（无 detector）。

**判定标准**
- FAIL：基准与策略标的错配（如 A 股策略对比无风险利率 / 自定义组合）；超额计算口径前后不一致。
- WARN：基准未声明或无风险利率取值未说明。
- PASS：基准可比、口径一致、同时报告绝对与超额，且说明风格暴露差异。

**修复指引**：选可比基准；口径一致；补充多因子剥离后的超额归因。

---

## 轴 9：报告透明度（Reporting transparency）

**判定什么**：关键假设是否披露；结果是否可复现（数据、参数、代码版本）。

**证据来源**
- 代码取证 / 报告审读：是否列出样本区间、股票池、成本、成交假设、参数、数据版本。

**判定标准**
- FAIL：结论数字无法从披露信息重算（缺数据来源、参数、样本区间）。
- WARN：主要假设披露不全（如成本只写"已含"）。
- PASS：数据 / 参数 / 代码版本 / 假设全部可追溯，他人可重算。

**修复指引**：固定随机种子与数据版本；附假设清单与复现步骤。
